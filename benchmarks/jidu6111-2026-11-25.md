# JIDU6111 initial measurement — 2026-11-25

Measured on the actual JioRouter AX6000 JIDU6111, OpenWrt SNAPSHOT r0+38470-c3af7ee2f2, kernel6.18.60, monitor packages1.0.0-r2. No forwarding, Wi-Fi, offload or firewall settings changed. Only telemetry was briefly stopped for the baseline and restarted afterward.

The supplied script captured sequential nominal60-second windows. The first five baseline seconds were excluded because service shutdown is asynchronous; all52 retained baseline observations show zero agent RSS. Telemetry sampling began after a10-second startup wait and contains58 observations. Raw CSV and machine summary are retained locally in ignored `benchmarks/results/`; private router measurements are not automatically published.

The running tree includes shell, log follower and live children; summing RSS counts shared pages repeatedly and can miss short-lived children. The parent-only status reading was1520KiB RSS, with0.099% CPU share of the whole machine at one status check. Those parent figures exclude curl and collectors. This firmware does not expose readable `smaps_rollup` for proportional-memory attribution, so unique memory consumption is unknown. The low-single-digit MiB target has **not** been demonstrated for the whole agent tree; its measured RSS sum reached12.5MiB and needs further investigation before making that claim.

The observed CPU difference was1.01 percentage points. Traffic and memory changed between windows, so this is not a causal measurement of agent overhead. The higher MemAvailable in the running window does not indicate that telemetry saves memory. WAN counters include other traffic and do not isolate upload volume. This run does not establish HTTPS-only bytes, peak transient allocation, flash-write auditing, packet-forwarding throughput, Wi-Fi impact, outage resource bounds or long-term stability. Repeat longer matched-load experiments before drawing those conclusions.
